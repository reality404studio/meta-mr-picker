# WebXR 반응 테스트 — 윤슬을 어디에 바를 것인가

> **앱 코드가 아니라 반응 측정용 장치예요.** `reference/texture-lab/` 과 같은 성격.
> 보드 과업이 아니고, `docs/DECIDED.md` 2026-11-04 「콘티 컨펌 전에는 새 기능을 구현하지 않는다」에
> 걸리지 않도록 `Assets/` 에는 아무것도 넣지 않았어요.

링크 하나로 열리는 페이지예요. 헤드셋이면 패스스루로 들어가고, 폰·노트북이면 책상이 있는 방을
흉내 낸 화면으로 열려요. 둘 다 같은 질문을 물어봐요: **담아 온 윤슬이 어느 표면에서 가장 살아나나.**

## 왜 만들었나

윤슬 쉐이더 반응이 좋았는데, 그 반응이 **물빛 자체**에 대한 것인지 **물빛이 엉뚱한 데서 되살아나는
것**에 대한 것인지는 아직 안 갈렸어요. 합격 기준 A5 는 "모은 텍스처는 내가 원하는 곳의 표면에서
재탄생한다" 인데, 재탄생이 일어나려면 재료와 표면 사이에 마찰이 있어야 해요. 이 페이지는 마찰이
0 인 쪽부터 큰 쪽까지 네 단계를 같은 물감으로 나란히 놓고 사람들한테 직접 눌러 보게 해요.

## 표면 네 개

| 키 | 무엇 | 셰이더에 일어나는 일 |
| --- | --- | --- |
| `BARE` | 아무것도 안 바른 책상 | 기준 샷 |
| `MAT` | 책상매트 — 60×40cm 평면 하나 | **2톤 램프가 꺼져요.** 평면은 노멀이 하나라 `dot(n, lightDir)` 이 상수고, 셀 밴드가 책상매트 전체에서 한 값이에요. 남는 건 색만 입힌 사진 |
| `CLOTH` | 같은 물감을 책상보로, 모서리 밖 20cm 까지 | 접힘이 노멀을 둘·셋으로 나눠서 램프가 윗면과 치맛단을 가름 |
| `THINGS` | 책상 위에 이미 있는 것들 (키보드·컵·병) | 트라이플래너가 제 일을 함. 곡면이라 노멀이 램프를 끝까지 쓸고 지나감 |
| `LIGHT` | 책상은 그대로, 물빛만 떨어짐 | 월드 공간 투영 + 가산. 아무것도 칠하지 않고 코스틱으로만 |

`CLOTH` 가 기본값이에요 (2026-11-04 사람 결정). 매트의 '책상 전체를 덮는다'는 기능은 그대로
두고 평면성만 깬 안이라, 네 개 중 가장 적게 벗어나면서 램프가 살아나는 자리예요.
`MAT` 은 사람이 먼저 떠올린 안이자 비교 기준선이라 그대로 남겨 뒀어요.

`STILL` / `LOOP` 로 물감을 바꾸고, `POUR` 또는 표면을 집으면 버킷 채우기가 다시 돌아요
(`docs/DECIDED.md` 2026-11-04 「dab 은 버킷 채우기」).

## 돌리는 법

정적 파일이라 아무 HTTPS 호스팅이나 되고, 바깥으로 아무것도 안 불러요 (three.js 는 `vendor/` 에
같이 넣었어요 — 앱 규칙 "외부 서비스를 빼도 동작"). 웹폰트만 Google Fonts 에서 받고, 못 받으면
시스템 고정폭으로 떨어져요.

```bash
cd reference/webxr-reaction && python3 -m http.server 8765
```

Quest 에서 열려면 **HTTPS 가 필수**예요 (WebXR 요구사항). GitHub Pages 로 올리는 게 제일 빠르고,
`https://<user>.github.io/<repo>/reference/webxr-reaction/` 로 열려요. 헤드셋에서 Quest Browser →
그 주소 → `Enter passthrough`. 책상을 어떻게 잡는지는 아래 「내 진짜 책상에 깔기」를 보세요.
자리가 잡히면 핀치는 물감 붓기, 책상 너머 떠 있는 판을 핀치하면 표면이 바뀌어요. 컨트롤러 없이 손만으로 돼요.

## 내 진짜 책상에 깔기

세 단계로 시도해요. 위에서부터 되는 게 잡혀요.

1. **Quest 공간 설정(Space Setup)에 책상이 있으면 자동.** `plane-detection` 으로 수평면 중
   높이 0.45~1.25m 짜리를 찾고, `semanticLabel` 이 desk·table 인 걸 우선해요. 책상의 **진짜
   가로·세로**가 들어와서 책상보가 그 크기로 다시 만들어져요. 세팅 0번.
2. **양손 사각형** (`docs/DECIDED.md` 2026-11-04 [공통]). 양손을 동시에 핀치해서 책상의 **대각
   두 모서리**를 짚으면, 두 점의 평균 높이 = 책상 높이, 두 점의 가로·세로 간격 = 책상 크기예요.
   짚는 동안 흰 사각형이 떠요. 떼면 확정. 언제든 다시 해서 고칠 수 있어요.
   손이 기울어도 **머리 방향 기준으로 각을 세워서** 책상보가 비뚤어지지 않아요 — 옛 채집
   사각형이 기울기 때문에 폐기된 걸 피한 거예요 (`REJECTED.md` 2026-11-04).
3. **조준 링 한 번 찍기** — 위 둘이 다 안 되면.

책상 크기가 바뀌면 책상보·매트·빛 평면이 **그 크기로 다시 만들어져요** (스케일로 늘리지 않아요 —
늘리면 노멀이 비뚤어져서 2톤 램프가 깨지고 물감이 늘어나요). 물감 밀도는 월드 기준이라 책상이
커져도 무늬 크기는 그대로예요.

## 헤드셋에서 주소 치기 싫을 때

- **MQDH** — 이미 캐스팅에 쓰고 계시니 제일 빠릅니다. Device Manager → Browser 에 주소 넣으면 헤드셋에서 열려요.
- **ADB** — `adb shell am start -a android.intent.action.VIEW -d "<https 주소>"`
- **Meta Quest 폰 앱 공유 시트** — 폰 브라우저에서 링크 공유 → Quest 앱 선택 → 헤드셋에서 바로 열기. 남들한테 돌릴 때 이게 제일 쉬워요.
- **Web Launch** — 사이트가 "헤드셋에서 열기" 링크를 넣을 수 있어요. oculus.com 의 `open_url` 주소에 대상 URL 을 인코딩해 넣는 형식이고 **HTTPS 만** 됩니다. 정확한 템플릿은 Meta 공식 문서에서 확인하세요 (이 세션에선 `developers.meta.com` 이 막혀 있어 템플릿을 직접 확인하지 못했어요).

## 이 데모가 **못** 하는 것 (중요)

- **채집을 못 해요.** WebXR 에는 패스스루 카메라 픽셀 접근이 없어요. 그래서 `A1` 핵심 루프의 앞쪽
  절반(응시 → 펀치 → 시야가 텍스처가 됨)은 여기서 재현이 안 되고, **이미 담아 둔 윤슬을 바르는
  뒤쪽 절반만** 보여 줘요. 이건 Quest 네이티브(PCA)에서만 돼요. 이 페이지를 앱 데모로 쓰면 안 돼요.
- **서버가 없어요.** 반응 집계는 `localStorage` 라 그 기기 안에만 남아요. `COPY TALLY` 로 긁어서
  받는 식이에요. 여러 사람 반응을 한곳에 모으려면 백엔드가 따로 필요해요.
- **루프가 아직 주기화 전이에요.** `assets/yunseul_loop.webm` 은 PR #1 의 크로스페이드 루프라
  이음매가 남아 있어요. 그래서 `LOOP` 일 때는 미러 반복 + 반복 밀도 0.34배로 눌러 놨어요.
  `PeriodicTile` 을 프레임마다 돌리면 `STILL` 처럼 촘촘히 깔 수 있어요.
- 손 관절을 직접 읽지 않고 `select`(핀치) 이벤트만 써요. 핀치 유지·드래그 같은 건 없어요.

## 검증

Playwright(헤드리스 Chromium)로 다섯 표면을 전부 렌더해서 콘솔 에러 0 을 확인하고,
표면 전환·버킷 붓기·루프 재생·집계 버튼을 실제로 눌러 봤어요. 검사 스크립트는 일회용이라
레포에 넣지 않았어요. 헤드셋 경로(`immersive-ar`, hit-test,
핀치)는 **아직 실기 미검증**이에요 — Quest 에서 한 번 열어 봐야 해요.
